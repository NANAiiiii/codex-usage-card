# 自动启动助手：工作原理与维护

非官方 Windows 实验版。主窗口结构、应用更新及 Windows 正常退出行为都可能影响接管，不保证每次成功。

## 当前接管规则

1. 用户启用后，登录启动项运行助手；入口通过真实 Explorer 桌面启动独立监听，不依附于 Codex 的进程生命周期。
2. 预检 Node.js、CLI 发现和 Windows 包激活接口，完成预检前不操作客户端。助手只监听当前用户会话的已注册 WindowsApps Codex 路径。
3. 排除监听开始前已存在的进程。新进程约 1.5–30 秒内、处于前台且只有一个正常顶层窗口时才考虑接管。30 秒是上限，不是必须等满；鼠标和键盘输入不再阻止接管。
4. 如有指定 Codex 的纯本机 39222 监听，直接加载额度，不重启；非预期监听会被拒绝连接，不关闭或篡改占用者。
5. 否则遵守两分钟冷却，先持久记录尝试，再检查候选主窗口仍为前台、Ctrl/Shift/Alt/Win/Q 均未按住，一次性发送客户端退出快捷键 Ctrl+Q。不抢焦点、不使用窗口关闭或 Restart Manager 会话结束。不强杀、不反复重试；遇到退出确认不代替用户确认。等待最多 10 秒；仍未退出则取消接管。
6. 正常退出后额外等待 3 秒，给 Windows 包及托盘资源留出释放时间；期间停止信号或新实例会取消重开。否则通过已注册包激活 Codex，带本机调试参数重开，加载圆环。重开后的短期抑制及已处理进程记录防止循环。

被跳过的进程不会等你开始工作后再突然重试。拒绝退出、超时、窗口在后台、多窗口、旧会话或超过上限，都可能导致没有圆环。`runtime/auto-status.txt` 和 `auto-assistant.log` 记录原因。`runtime/status.json` 可能来自旧进程，判断当前是否成功必须同时核对时间、活动进程及 `state=placed`。

## 风险与适用范围

- **键鼠输入期间仍可能重开 Codex，打断刚开始的打字或任务、切换焦点。** 不接受该行为请不要启用；这不是无打断的官方集成。
- 程序不修改安装包、不提权、不使用强制退出标志。退出请求可能被系统或客户端拒绝。
- Ctrl+Q 使用系统 SendInput，发送前核验目标窗口及按键状态，但 Windows 不提供原子性的“核验前台并仅向该窗口发键”。瞬间焦点切换仍可能让快捷键落入其他应用；不能接受此风险请停用。自定义/禁用快捷键、应用更新、退出确认或权限差异可能导致接管失败；不会重试或提升权限。
- 已打开的工作会话不接管，无法在现有无调试参数进程上补开调试端口。
- CDP 39222 仅绑定本机，连接前检查进程及地址；接口权限很高，localhost 不是身份认证。不要转发端口。
- 停止监听不等于停止额度后台组件或关闭调试端口；彻底关闭端口需完全退出 Codex。
- 原 macOS 上游也采用受保护的启动重开，但本 Windows 版本的“允许键鼠输入”策略不同，不是逐行移植，也不是上游维护的版本。

## 管理、更新与卸载

命令及可选的“管理工具”快捷方式见 [README](../README.md)。启用通过 EXE 直接创建当前用户 Startup 中的 `Codex Usage AutoHelper.lnk`，无需预先生成管理快捷方式。停用只删除经目标路径及参数归属核对的本工具入口，不操作其他启动项。

更新或移动目录前：先在旧目录执行 `./Codex-Usage-AutoHelper.exe --disable`，保存工作并完全退出 Codex，确认旧目录的助手及额度后台组件退出，再解压新版本、启用新目录。新旧目录不要同时运行；不要在活动程序上覆盖 EXE，也不要删除活动锁或冷却记录强行接管。

卸载按同样的停用、退出流程完成，再删除本工具目录及属于它的快捷方式。不要递归删除整个 Startup 或开始菜单目录。助手不卸载 Codex。

本地 runtime/ 包含状态、活动锁、进程号、日志及冷却记录，不保存按键文字、聊天内容或登录令牌，不提交 GitHub。

## 验证范围

2026-11-03：0.1.2 使用 Ctrl+Q 应用退出，用户按原图标启动测试后确认正常。日志对应应用退出请求、进程消失、3 秒缓冲和重开；随后主窗口额度为 placed 并继续刷新。本次修复后的电脑重启尚未复测。被替换的退出方式及问题经过见[Changelog](https://github.com/NANAiiiii/codex-usage-card/blob/windows/CHANGELOG.md)。

旧版在 2026-11-02 曾验证原图标启动和电脑重启后的登录自启，不将该结果自动视为新退出方式的重启验收。0.1.2 的门禁包括 Node 回归、原生策略自检、冷启动边界、退出快捷键布局/保护/部分提交及重开缓冲取消测试；纯策略测试不发送按键，也不代表真实启动验收。Explorer 独立生命周期设计保持不变。

其他设备、所有 Windows/Codex 版本、长期运行和所有退出拒绝场景尚未全面验证，不能称稳定版或普遍兼容。此前的输入保护跳过已通过明确改变策略消除，不代表识别出了原始输入来源。
