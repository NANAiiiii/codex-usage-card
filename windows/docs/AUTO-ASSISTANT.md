# 自动启动助手（实验版）

这不是 Codex 官方插件。主窗口检测、退出行为和应用更新可能影响接管；目前仅针对本机 WindowsApps 打包版实现。

## 使用入口

- **启用自动启动助手**：运行助手，并注册本用户登录启动快捷方式。
- **停用自动启动助手**：退出助手，并删除经归属核对的本工具登录启动快捷方式。不关闭 Codex，不停止已经运行的额度监视器。
- **自动启动助手**：仅运行到本次退出或注销，不改变登录启动配置。
- **退出自动启动助手**：只退出这次后台监听，保留登录启动配置。
- **自动助手状态**：显示最近动作和是否已设置登录启动。

首次启用时，已经打开的 Codex 不会被重启。下一次请先正常退出 Codex，然后从**原来的官方图标**打开，启动后短暂停留，圆环接管可能需要数秒。

## 接管条件

助手每秒检查当前用户会话中已注册 Codex 路径的窗口。只有新进程、启动约 1.5–8 秒内、前台窗口、只有一个正常顶层窗口、启动后没有其他输入且不在两分钟冷却内，才考虑接管。

如果已经有调试端口，只调用内部后台组件接管额度，不请求退出。后台组件仍会检查端口是否由指定 Codex 监听且只绑定本机。

否则，先持久记录一次尝试，再按 PID 和创建时间向 Windows Restart Manager 请求**正常退出**，不使用强制退出标志，不结束其他应用、服务或用户会话。拒绝或超时不强杀、不反复尝试。成功退出后再次检查输入和新实例，然后调用内部后台组件重开客户端并显示卡片。

这和 macOS 上游只是相似思路，不是对其原生启动桥的逐行移植。

## 局限和风险

- 没有输入也不代表应用没有后台任务；刚启动就需要恢复后台任务的用户应停用助手。
- 仅关闭窗口可能收进托盘，系统退出请求也可能被拒绝。出现跳过状态不要放宽保护条件或反复点击。
- 退出后如果检测到新的用户输入，助手会取消重开，避免抢焦点；此时可能需要你手动打开 Codex。
- 自动重开与用户动作仍存在时序竞争，不能保证完全无闪烁、绝不切换焦点或覆盖所有客户端版本。
- 尚未完成多设备兼容验证，不应宣称稳定版或普遍兼容。
- 仍需本机高权限调试接口。停止监听不关闭已经打开的调试端口；需要完全退出 Codex。

## 本地文件与卸载

助手 EXE、源码、日志均位于项目目录。`runtime/auto-assistant.log`、`auto-status.txt`、`auto-last-attempt.txt` 保存动作、进程号及冷却时间，不保存键盘文字、聊天内容、账号令牌。
先运行便携目录的 `create-shortcuts.ps1`，五个入口只放在“管理工具”子目录，不创建开始菜单入口。启用后在当前用户的 Startup 文件夹额外创建 `Codex Usage AutoHelper.lnk`。
卸载前先“停用自动启动助手”，完全退出 Codex，确认后台额度组件退出，再删除这些专用快捷方式和项目目录。不要递归删除整个 Startup 或开始菜单目录。

## 验证范围

策略自检与现有会话基线保护可在不关闭 Codex 的情况下验证。**真实原图标启动→正常退出→带卡片重开的全过程尚需用户测试，不能用策略自检代替。**
